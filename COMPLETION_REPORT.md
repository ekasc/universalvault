# UniversalVault completion status

This file records what the app does, how to reproduce the checks, and what still needs a person. The results below come from the run on 2026-10-31.

## Implemented

- Creating, unlocking, recovering, and authenticating a protected field can be cancelled at any stage.
- Saves compare bytes across processes. A conflict reports that the vault changed in another session and asks for a lock and unlock before saving again.
- Every payload is validated on load. Legacy secrets are normalized, empty dates stay empty, and an unsupported schema version is rejected rather than migrated.
- Insertion is authorized against the field that had focus, and keyboard chunks split on UTF-16 boundaries.
- Undo and redo are bounded by the session. Items, fields, and categories can be reordered, and categories collapse.
- An encrypted backup can restore a vault, and recovery keeps the original encrypted file.
- Backup encryption runs off the main thread. Import is bounded, confirms the item count and passphrase, and commits only against the generation it started with.
- Authentication controls report their busy state, errors appear in the window, previews are masked, and the palette names its target.
- The application icon is generated by script. Release and debug verification bundles are built separately.

## Reproduce the results

`bash scripts/verify.sh` runs the test suite, compiles release, races two processes on the storage path, packages the app, validates the signature, and checks that release builds reject verification flags before touching storage.

`bash scripts/verify.sh --native` also drives the real views with synthetic authentication and throwaway storage. It does not open the personal vault or the real Keychain. It reuses any Accessibility permission already granted and does not change TCC settings.

- Category creation ran through the sidebar footer menu and the name sheet, persisted, and selected the new category.

- Window screenshots cover light and dark editors, locked and empty states, Settings, masked palette results, and backup sheets.
- Release packaging passed Info.plist and signature checks. The bundle is signed with the Apple Development identity and embeds the Mac Team provisioning profile when one is installed. Without a profile it falls back to ad-hoc signing. Release verification flags exit before storage access.
- The closing process and temporary-directory sweep found no verification processes and no synthetic vault directories left behind.

## Not yet verified

- Real Touch ID, password entry, Keychain access control, and cancellation of a real system prompt. Vault creation and unlock with real Touch ID passed interactively on 2026-10-25 against the signed build. Cancelling a real system prompt is still unverified.
- Sleep and screen-lock notifications on the distribution build.
- VoiceOver announcements, Full Keyboard Access, and contrast under system accessibility settings.
- Menu dispatch for every scene command, the global shortcut in third-party applications, and compatibility with other applications.
- Successful creation from the Welcome window. Its busy, cancel, and denial paths have native coverage. The success path shares the vault window's creation code, which is covered.
- Native acceptance of item and field reordering, category rename and delete, profile creation, and each focused-scene command. Their domain and persistence rules pass automated tests; the interface interactions do not. Context menu traversal through Accessibility blocked the app in this environment, so rename and delete were dropped from the verification rather than left flaky.
- Command title and enablement refresh in an open menu. The verification cannot open a menu bar menu, so it no longer dispatches menu items.
- An accessible name for the toolbar search field that does not come from its placeholder. An explicit label needs a replacement search control, which would give up the native search behaviour.
- Developer ID signing, notarization, and continuity across signed updates. No Apple credentials are configured or changed.

## Guards

`scripts/check-invariants.sh` fails the build if any source file reads or writes the clipboard, or calls `print`, `debugPrint`, or `NSLog`. The verifier runs it first. Both properties were previously checked by eye only.

## CI

`.github/workflows/verify.yml` runs the headless verifier on a `macos-26` runner, uploads an ad-hoc app archive, and refuses to run when the macOS SDK is older than 26. The workflow is manual-only and has not run on GitHub; its YAML was checked by reading it, because no YAML parser is installed here. Native checks stay opt-in because hosted runners do not provide reliable permission or signed-in desktop state.
